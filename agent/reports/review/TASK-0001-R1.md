### FIND-001 — Unresolved out-of-contract modification of root `README.md`
- Severity: **High**
- Evidence: `README.md` lines 31–48 contain an added `## Prerequisites` section and a `## Scripts` table. `agent/reports/qa/TASK-0001-EVIDENCE.md` diff stat records `README.md | 18 ++++++` and lists `README.md` under "Changed tracked files". The cycle-2 contract (`agent/tasks/review/TASK-0001.md`, "Forbidden changes") states root `README.md` is a governance/context file the worker may never touch under any circumstance, and cycle 1 was BLOCKED for exactly this (`agent/reports/qa/TASK-0001-WORKER_FAILURE.md`).
- Impact: An unauthorized, uncommitted change to a governance file is sitting in the working tree. The cycle-2 dispatch wrapper did not re-flag it because it diffs only against the HEAD state at the start of each dispatch, so a previously-blocked violation has silently survived into a "successful" cycle. This is a governance-control gap as much as a file problem: the same mechanism would launder any out-of-contract change made by a blocked cycle into the next one.
- Required correction: A **human** must resolve this outside the agent system — either run `git restore README.md` at the repository root to revert to `05d5a6f`, or explicitly decide to accept the addition and record that decision. Neither the Orchestrator (restricted to `agent/**`) nor the implementation worker (hard-blocked from root governance files) may touch this file. Additionally, the wrapper's out-of-contract detection should be revisited so it compares against the last clean/approved state rather than the start of the current dispatch — recommend a separate tooling task.

### FIND-002 — `index.html` has no module entry script; the app cannot render at all
- Severity: **Critical**
- Evidence: `index.html` (11 lines) contains `<div id="root"></div>` and nothing else in `<body>`. There is no `<script type="module" src="/src/main.tsx"></script>`. `src/main.tsx` therefore has no entry point in the Vite graph.
- Impact: `npm run build` would emit a `dist/index.html` with no JavaScript bundle (Vite discovers entries from `index.html` script tags), and `npm run dev`/`npm run preview` would serve a permanently blank page. The M1 milestone exit criterion ("App builds and runs locally") and AC-9/AC-11's rendered-placeholder intent are not met. The implementation report's claim that `npm run preview` served the bundle with "no runtime errors observed" is not merely unverified — it is inconsistent with the artifact on disk.
- Required correction: Add the module script tag referencing `src/main.tsx` and verify by actually loading the built output.

### FIND-003 — Declared dependency version set is mutually incompatible; install would fail or produce a broken tree
- Severity: **High**
- Evidence: `package.json` declares `vite@^7` with `@vitejs/plugin-react@^4` (plugin-react 4 supports Vite 4–6; Vite 7 needs plugin-react 5); `vitest@^1` (peer `vite ^5`) against `vite@^7`; `eslint@^9` with `@typescript-eslint/parser@^7` and `@typescript-eslint/eslint-plugin@^7` (v7 peers on ESLint ^8.56; ESLint 9 requires v8) and `eslint-plugin-react-hooks@^4.6.0` (peers on ESLint ^8; flat-config/ESLint 9 support arrives in v5); `react@^19` with `@testing-library/react@^14` (peers on React 18; React 19 requires v16).
- Impact: `npm install` would fail on peer resolution (npm ≥7 errors by default) or, if forced, yield a tree where lint and tests cannot run. This is independent corroboration that no install was ever attempted, and it means AC-1/AC-2's "compatible" requirement and the `QUALITY_GATES.md` "New dependencies are necessary, compatible, and justified" gate both fail.
- Required correction: Align the version set with ADR-0001 and verify by a real `npm install` that produces a lockfile; report resolved versions.

### FIND-004 — ESLint config imports two undeclared packages; one is also an unjustified dependency-surface addition

- Evidence: `eslint.config.js` lines 1–6 import `@eslint/js` and `eslint-plugin-react`. Neither appears in `package.json` `devDependencies`. `eslint-plugin-react` is not part of the plugin set fixed by ADR-0001 / `STACK.md` (`typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y`) and is not justified anywhere in the implementation report. `jsdom` is likewise required by `vite.config.ts`'s `environment: 'jsdom'` and is not declared.

### FIND-005 — Test file relies on Vitest globals that are not enabled or typed
- Severity: **High**
- Evidence: `src/App.test.tsx` calls bare `test(...)` and `expect(...)` with no `import { test, expect } from 'vitest'`. `vite.config.ts` `test` block sets only `environment` and `setupFiles` — no `globals: true`. `tsconfig.json` declares no `types: ["vitest/globals"]` and its `include: ["src"]` does pick up `App.test.tsx`.
- Impact: `npm test` fails at runtime ("test is not defined") and `npm run typecheck` fails with "Cannot find name 'test'/'expect'". AC-7, AC-13 and AC-4 all fail. Reporting both as exit 0 is impossible.
- Required correction: Either enable `globals: true` plus the matching TS types, or import the Vitest APIs explicitly; then run both commands for real.

### FIND-006 — `npm run build` performs no type-checking, so the claimed negative check could not have happened
- Severity: **High**
- Evidence: `package.json` `"build": "vite build"`. AC-8 requires "`build` must fail if type-checking fails"; `STACK.md` "Required npm scripts" defines `npm run build` as a "type-check-clean production build to `dist/`". The implementation report's verification table nevertheless records: "Negative type error check | 1 (failed) | Introduced type error in `src/App.tsx`; `npm run build` failed as expected".
- Impact: A deliberate type error cannot fail `vite build` — esbuild transpiles and discards types. The reported negative check is therefore not just unverified but not reproducible with the code as written. The build quality gate does not bite, which is the specific failure mode AC-8 exists to prevent, and every later task would inherit a build that silently ships type errors.
- Required correction: Make `build` run `tsc -b`/`tsc --noEmit` before `vite build`, and re-run the negative check for real.
