## Forbidden changes
- Anything not listed in Allowed paths.
- **Pausing mid-task to ask a question instead of proceeding or reporting BLOCKED.** If a Bash command is denied or fails, try the `npm run <script>` form if you used a shorthand, retry once if it looks transient (e.g. a file-lock error); if it still fails, write the implementation report with `Status: BLOCKED` naming the exact command/error, and stop. Never end your turn on an open question with no report written.
- Suppressing a real type error with `// @ts-ignore`, `// @ts-expect-error`, a bare `as any`, or an `eslint-disable` comment instead of fixing it properly. A single targeted `as X`/`as unknown as X` assertion (matching a real, narrower type) on one expression is fine; a blanket `any` plus a disable comment is not.
- **Widening `.prettierignore` (or any lint/format ignore list) to exempt a file from a quality gate instead of making the file actually compliant.**
- **Overwriting Vitest's (or any tool's) default `include`/`exclude` list with a partial custom array without checking whether that silently drops needed defaults.** Prefer an `include` allow-list scoped to real source paths over an `exclude` deny-list when in doubt.
- Any file the build/typecheck toolchain emits must land inside a `.gitignore`d location (already correctly true for `.ts-build/` — keep it that way).
- **`README.md`, `AGENTS.md`, `CLAUDE.md`, `SETUP.md`** — governance/context files the wrapper hard-blocks unconditionally.
- Any file under `agent/**`, `.claude/**`, `.roo/**`, or `tools/**`.
- Product scope/behaviour beyond this contract.
- Adding any runtime dependency other than `react` and `react-dom`.
- Adding CI workflows, deployment configuration, hosting configuration, Dockerfiles, or PWA/service-worker files.
- Deleting or rewriting pre-existing repository files other than the five stale files explicitly listed as delete-only above.
- Using `npm install`/`npm ci` with `--force` or `--legacy-peer-deps`.
- Production deployment, release, `git push`, merge, tag, force operations, or destructive Git commands. Committing is the Orchestrator's decision, not the worker's.
